카카오 여행 문의를 안전하게 예약 리드로 변환하는 오픈소스 예제

서명된 웹훅을 검증하고 규칙 기반으로 예약 정보를 추출해 고객과 Booking 리드를 저장합니다. 실제 CRM·Google Sheets·WeChat·모델 연동은 아직 구현되지 않았습니다.

Node HTTP · Zod · 테스트됨

현재 구현된 데이터 흐름

  1. 카카오 웹훅의 HMAC 서명과 256 KiB 본문 제한을 확인합니다.
  2. JSON과 Zod 스키마를 통과한 메시지만 파이프라인으로 전달합니다.
  3. 규칙 기반 파서가 목적지, 날짜, 인원, 상품명과 연락처를 추출합니다.
  4. PostgreSQL이 이벤트 lease, 고객 식별자, Booking 리드를 저장합니다.
  5. 개발 환경에서는 fake 외부 어댑터를 사용하며, 운영 시작은 차단됩니다.

현재 안전 기준

중복 처리, 고객 식별자 충돌, 민감정보 로그, 잘못된 OAuth 상태를 기본 실패 경로로 검증합니다. 필수 예약 정보가 없거나 날짜가 잘못되면 Booking 리드를 만들지 않고 needs_confirmation을 반환합니다.

MVP API 엔드포인트

GET /health현재 프로세스의 서비스 상태를 확인합니다. GET /auth/kakao/login카카오 OAuth 인가 URL을 생성합니다. GET /auth/kakao/callback카카오 인가 코드를 토큰으로 교환합니다. POST /webhooks/kakao상담 메시지를 내부 고객 기록과 Booking 리드로 변환합니다.

Before Production

운영 전 남은 검증

실제 PostgreSQL마이그레이션, 동시성, lease 인계를 실제 데이터베이스에서 검증해야 합니다.
실제 외부 어댑터CRM과 Sheets 연동에 제한 시간, 취소, 재시도 분류, 하위 시스템 멱등성이 필요합니다.
OAuth 상태 저장소현재 쿠키 기반 상태를 원자적 일회용 TTL 저장소로 교체해야 합니다.
운영 경계엣지 rate limit, 비밀 저장·회전, 로그 보존, 백업·복구 절차를 검증해야 합니다.

Kakao OAuth

구현된 OAuth 경계

인가 URL 생성, 상태 쿠키 검증, 인가 코드의 토큰 교환까지 구현했습니다. 카카오 사용자 프로필 조회와 CRM 고객 연결은 아직 구현되지 않았습니다.

  1. REST API 키 설정Kakao Developers에서 앱을 만들고 Redirect URI를 등록합니다.
  2. 인가 URL 생성무작위 state를 HttpOnly, SameSite 쿠키에 저장하고 로그인 URL에 포함합니다.
  3. 콜백 검증/auth/kakao/callback에서 쿼리 상태와 쿠키를 timing-safe 방식으로 비교한 뒤 쿠키를 지웁니다.
  4. 토큰 교환5초 제한과 응답 스키마 검증을 적용하고 토큰 값은 HTTP 응답에 노출하지 않습니다.
